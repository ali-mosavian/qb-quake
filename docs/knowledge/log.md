Root cause required abandoning BASIC's own memory introspection (`memAvail&`/`SETMEM`/`FRE`, which measure BASIC's far-heap *size*, not DOS's actual free memory) and walking DOS's MCB chain live in the dosbox-x debugger instead: DOS had exactly 9,312 bytes free system-wide, so the 16 KB request was arithmetically impossible to satisfy honestly — mgl's `bas_malloc` retry path (shrink BASIC's heap via `B$SETM`, retry `int 21h/48h`) handed back a block that didn't correspond to real headroom on an arena this fragmented, and a bare `REDIM`'s zero-init then corrupted whatever was actually there. Fix identified: move `lm_base` (71,328 B) + `lm_info` (36,704 B) to XMS, reclaiming 108 KB; UMB is already linked and already fully consumed, not an available lever.
